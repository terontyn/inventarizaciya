# Установка и миграции

## Чистая установка и публичная V7/V2
Asset использует неизменные V1–V7 и новую V15 schema-only. User использует неизменные V1–V2 и V5. Пропуски версий зарезервированы для отдельной legacy-линии. В default migrations нет demo seed.

## Существующие private V14/V4
Не запускать default upgrade вслепую: Flyway должен отвергнуть отсутствующие legacy scripts. Из своей сохранённой private версии получите точные исходные asset V8–V14 и user V3–V4 в отдельные каталоги. Не публикуйте их и не редактируйте checksum. Для asset V12 существовали два варианта: взять именно тот, который применён в этой БД.

На копии своей БД укажите LEGACY_ASSET_MIGRATIONS_DIR и LEGACY_USER_MIGRATIONS_DIR и профиль legacy-v14. Профиль требует уже применённую версию 14/4, включает исходные filesystem migrations и затем применяет forward V15/V5. Никаких repair, ignoreMissing или удаления истории. Если checksums/версии отличаются, остановиться и исследовать схему и архивы.

V15 создаёт недостающие таблицы/колонки без demo строк, сохраняя существующие обращения, SIM-карты, картриджи и QR. Переиздание QR по id и старые напечатанные метки требуют отдельной приёмки. Для legacy данных тестировать на PostgreSQL: старый user V3 несовместим с H2. Чистый demo не использует старые seed migrations.

Неизвестная или частично применённая legacy схема не поддерживается автоматическим продолжением. Проверка PostgreSQL upgrade обязательна до рабочей установки.
