# Локальная демонстрация
Требуется Java 17. Без Docker и внешних API можно запустить два сервиса с профилем demo:

```sh
./gradlew :services:user-service:bootRun --args='--spring.profiles.active=demo'
# Во втором терминале
./gradlew :services:asset-service:bootRun --args='--spring.profiles.active=demo'
```

Откройте http://127.0.0.1:8781. Демо использует настоящий backend, H2 file database и вымышленные seed rows из ресурсов demo/seed.sql. Данные в demo-state сохраняются после reload и повторного запуска. Перед демонстрацией используйте новую рабочую папку, не рабочую БД. API и demo слушают только loopback; профиль demo не предназначен для сервера.

Выбор пользователя/роли в интерфейсе — pilot-механизм, а не проверка пароля. Отдельный frontend-redesign в другом PR остаётся визуальным прототипом и сюда не подменяет API. Полные складские/maintenance/software/ticket/reporting сценарии требуют остальных сервисов и не входят в двухсервисное демо.

В форме «Контекст доступа» укажите:
- Tenant: `00000000-0000-0000-0000-000000000001`
- Пользователь: `a1111111-1111-1111-1111-111111111111`
- Действующее лицо: `demo-user`
- Адрес сервиса пользователей: `http://127.0.0.1:8780`

Нажмите «Подключить». Должны появиться два пользователя, два актива и одна локация. Это вымышленные идентификаторы из seed.sql, не пароли. Изменяйте только данные demo-профиля. После reload контекст доступа и изменения актива сохраняются локально. Для сброса используйте отдельную новую папку demo-state при остановленных сервисах.
